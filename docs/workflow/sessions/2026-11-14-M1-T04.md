## Decisions and deviations

- ADRs: none. No open decision settled. No canonical name added or renamed (`Command` was already canonical).
- Gap: no task text says which task creates `Command`, although `Game.apply` needs it and M1-T07 snapshots its shape. Created here, with the full canonical shape, so M1-T05 does not change it.
- Interpretation 1: the mine cell stays hidden in the cell states after a loss (`CellView` has no mine variant; counting it as revealed would break the M1-T06 win rule). Mines show through `exposedMines`.
- Interpretation 2: "the first accepted command" is read as the first command that takes effect.
- Interpretation 3: result order of the flood fill is fixed (clicked cell first, discovery order, most recently found zero cell expanded first, neighbors ascending) and pinned by tests.
- Interpretation 4: flags cannot be placed before M1-T05, so cell-level flag rules are tested on the internal `revealCell` with hand-set states; the Game-level flag check is a `TODO(M1-T05)`.
- Scope edge: after a loss every command returns `[]`. This is the minimum needed so a lost game stays lost; M1-T06 owns the full post-game suite and win detection. Until then a game with all safe cells open stays `'playing'`.
- `flag`, `chord` and any unknown `type` return `[]` (`TODO(M1-T05)`).
- Test clock: `Date.now`, best of three runs, because the engine test tsconfig has no `performance` type.
