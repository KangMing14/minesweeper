## Decisions and deviations

- No ADR written, no open decision settled (D-01 to D-14 untouched), no canonical name added or renamed.
- The task asks for a snapshot of exported names and the type shapes of `Command`, `GameEvent`, `GameView`. Runtime exports cannot show types, so the test renders every export of `index.ts` with the TypeScript compiler API and compares the text with `__snapshots__/api-surface.txt`. The engine code stays pure; `typescript` (a root devDependency, no new dependency, no new pin) is imported in a test only. The test locates the source through `expect.getState().testPath` because the engine has no Node types and lint bans `node:*` imports there.
- Two test files instead of one: the "only `index.ts` imports" claim is easy to see when the file that makes it imports nothing else.
- Added the `@internal` check from the M0 re-review (finding N3, third gap) because it belongs to the API-surface test. Not done: `jsdoc/require-description` for engine and protocol, and the one-sentence note in the guide that `@internal` goes on its own line (N3 gaps 1 and 2).
- Threshold numbers (95 and 90) are my choice within the task's example of 90% branches; every engine file was at 100%. They are scoped to the engine only; `index.ts` barrels are excluded for every package, so the coverage table no longer lists the empty `index.ts` of `protocol` and the apps.
- Not done by design: the `m1-complete` tag, which follows the milestone review (`HOW_TO_USE.md`, section 7).
