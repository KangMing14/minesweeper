## Decisions and deviations

- ADR-009 written (settles D-04). No canonical name added or renamed.
- Gap 1 (settled in ADR-009): the task text does not say what a chord that reaches a mine emits. Decided: safe neighbors open first, then `cellsRevealed` followed by one `gameLost` with the lowest-index mine; a chord whose only target is a mine emits `gameLost` alone.
- Gap 2 (settled in ADR-009): a flag that takes effect moves `'ready'` to `'playing'`, following the M1-T04 reading of "the first accepted command".
- Gap 3: a delivery rule for a command with two events. Every event reaches every subscriber even if one throws; the first error is rethrown at the end. The existing single-event path in `#reveal` is unchanged.
- Interpretation: a chord needs the clicked cell to show 1 or more; flags are counted without checking them against the mines.

## Follow-ups

- ADR-010 (M4-T03): the rule "more safe cells revealed wins" uses `revealedCount` at a DNF, which includes the safe cells a losing chord opened first. ADR-010 should confirm this or supersede that part of ADR-009.
- M2-T02: the safe opening belongs to the first reveal; a flag can now be the first command that takes effect.
- M1-T06: win detection must also fire from a chord that opens the last safe cell (today a chord that opens the last safe cell leaves the game `'playing'`). Add that case to its tests.
- M1-T07: `chordCells` and `ChordResult` must stay out of the API-surface snapshot.
