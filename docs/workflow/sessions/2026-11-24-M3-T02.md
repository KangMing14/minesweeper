## Decisions and deviations

- ADRs written or updated: none. No open decision settled. ADR-004 says the signatures are created in M3-T02 and recorded in `ARCHITECTURE.md`; ADR-002 says `Clock` is an interface in `engine`; both hold, so no erratum.
- Stopped and asked before coding (CLAUDE.md rule 4 and the user's step 6): the milestone fixes seven members for `GameSession` but the task wants the session to report a stuck game, which none of them can carry. The developer chose option A (2026-11-24): an eighth member, `isStuck(): boolean`, on the interface. Recorded in `DECISIONS.md`, `ARCHITECTURE.md` and the M3 and M5 milestone files.
- Choices the task text left open: a second `start()` and a `start()` after `dispose()` do nothing; `view()` before a successful `start()` throws an `Error`; a bad config or seed throws from `start()` and leaves the session not started; a clock that returns `NaN` or `Infinity` counts as no time passing; the previous stamp moves on every command that reaches the engine, accepted or not; `elapsedMs()` also freezes when stuck and at `dispose()`; the session counts "accepted" as "produced at least one event" (checked at the limit by two tests, not by a log comparison, because the interface has no log); a command that makes the log exactly 100,000 long and ends the game does not make the game stuck.
- Deviations: (1) the acceptance line "no UI code imports `engine` directly except through the session and view types" is read as "no UI code creates or drives a `Game`", because the menu needs `PRESETS` (M3-T05); it is a code-review convention, not a lint rule. (2) The milestone files M3 and M5 were edited at close-out, outside the task's own file list, so that the fixed interface they quote is not stale; the edits are one sentence each.
