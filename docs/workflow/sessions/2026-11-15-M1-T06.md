## Decisions and deviations

- No ADR written, no open decision settled, no canonical name added.
- Gap 1: the docs do not fix the event order of a winning command. Decided: `cellsRevealed` then `gameWon { t }`, mirroring a losing chord. Recorded in `ARCHITECTURE.md`; it is not an ADR because nothing outside the engine's own event stream depends on it beyond what M5 will read from the code.
- Gap 2: `fast-check` was required by the task but missing from `package.json` and the pin table. Added as 4.10.2 with a registry check and a note in `DECISIONS.md`.
- Gap 3: "commands before the start signal" (Review Focus #2) is a match concern (M5-T04, M6-T04), not an engine one; the engine's only pre-start state is `'ready'`.
- Interpretation: a chord that reaches a mine is a loss and cannot also be a win, because it can only reach a mine while a flag sits on a safe cell, which stays closed. Pinned by a property test.
- `#reveal` now announces through the shared step (it used to emit one event directly); the single-event behavior for subscribers is unchanged.
