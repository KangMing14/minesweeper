## Decisions and deviations

- ADRs: none. No open decision settled. No canonical name added or renamed.
- Interpretation 1: the docs name the `GameEvent` variants but not the discriminant. Chosen: `type` with `'cellsRevealed' | 'flagToggled' | 'gameWon' | 'gameLost'`.
- Interpretation 2: `Game` has no way to change state until M1-T04, so the view is built by the pure internal `buildGameView(board, cellStates, status)`. This lets revealed, flagged, won and lost views be tested now. `Game` itself cannot yet be tested for event delivery; that check is marked `TODO(M1-T04)` in `game.test.ts`. The emitter is tested on its own.
- Interpretation 3: `exposedMines` lists mines by scanning `Board.isMine`; no method was added to `Board` (M1-T02 follow-up).
- Choice: a listener that throws does not stop the other listeners; the first error is rethrown after all have run.
- D-14: the engine view exposes mines when a player's own game ends. The server must withhold them in a race until the match result is final for both players (M5-T05 leak test). Recorded in `ARCHITECTURE.md` and the `GameView` TSDoc.
