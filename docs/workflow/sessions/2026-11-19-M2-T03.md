## Decisions and deviations
- ADRs written or updated: none. No open decision closed. No dependency added.
- Decided with the developer before coding (2026-11-19): the task says `createGame` returns a `'ready'` game after the opening reveal, but under the M1 rules any command that takes effect moves `'ready'` to `'playing'` and an opening can clear the board. Option A1: `new Game(board)` unchanged; the opening is revealed through an optional constructor parameter with no event, log entry or status change; `'ready'` until the first accepted command, `'won'` at creation if the opening clears the board. Recorded in `ARCHITECTURE.md` and noted in `DECISIONS.md`, not in an ADR.
- Deviation from the task text: valid `t` is a non-negative safe integer (the task says non-negative integer), so every logged `t` is exact in JSON.
- Deviation from "existing M1 tests still pass": `game.property.test.ts` changed (generator only), because random unordered `t` would now make the engine reject most commands and weaken its properties. Agreed with the developer.
