# Changelog

All notable changes to this project are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Entries are drafted from the conventional commits at task close-out and then curated by hand; each names its task ID. Versions start at `v0.<n>.0` for pre-launch releases and `v1.0.0` at public launch (see [DEVELOPMENT_GUIDE.md](DEVELOPMENT_GUIDE.md), "Tags and releases").

## [Unreleased]

### Added
- **M3-T04** Input controller. `apps/web/src/input/InputController.ts` (canonical name) turns mouse and keyboard events on the board into `PlayerAction`s for `GameSession.dispatch`. **Mouse:** a gesture is every button pressed until all are released and acts once, at the cell under the pointer on the last release (as in the classic game): left reveals, right flags, middle chords, left and right together chord (in either release order, once), and a left click on a revealed number chords too (option `chordOnNumberClick`, on by default; a reveal there did nothing before). A release over a gap or outside the board does nothing and is never read as cell 0; leaving the element cancels a gesture; a press with Ctrl held is ignored (a right click on macOS, which must not reveal); the context menu is suppressed. **Keyboard:** arrows move a cursor one cell and stop at the edges (no wrap to the next row), Space reveals, F flags, Enter or C chords. The ring is hidden until a key is pressed and the first key only shows it (in the middle, or where the last click or key left it), so a key never acts on a cell the player has not seen marked; holding a key repeats a move but not an action; keys with Ctrl, Meta or Alt, and keys it does not use (Tab, R, Shift+R), go to the browser. After a mouse click the ring is hidden and the clicked cell is remembered; on blur the ring is hidden. Once the game is won, lost or stuck (`isStuck()`) no action is sent. `attach(element)` makes the element focusable if it has no `tabindex` and `detach()` undoes only what it added. **Interface change, approved by the developer on 2026-11-25 (option (a) of the note in `DECISIONS.md`):** `BoardRenderer` gets a sixth member, `setCursor(index: CellIndex | null): void`, and `CanvasBoardRenderer` draws the cursor as a frame of four rectangles in the accent color over the cell, redrawing only the cell that loses the ring and the cell that gets it; the cursor is remembered across `render`, `resize`, `unmount` and `mount`, dropped when a new board is smaller than it, and an index that is not a whole number inside the board throws `RangeError` and keeps the old cursor. `BoardTheme` gains `accent`, read from the existing `--ms-color-accent` token (fallback `blue`); no new token. The controller also reads the read-only `session.view()` (board size, status), which the developer approved against the task's "`hitTest` and `dispatch` only". 56 new tests (969 in all): 37 controller tests against a fake session and a fake renderer, 5 component tests that play and win a seeded 6x6 game with the keyboard alone through `LocalSession`, `BoardCanvas` and the real renderer on a fake context, 11 for `setCursor`, and 3 for the contrast of the accent on the hidden and the revealed cell in every theme (at least 3:1); the `BoardCanvas` spy renderer gained a `setCursor` stub. A hand mutation check of 10 behaviors (no edge clamp, an action repeating while a key is held, the first key acting, keys acting after the game ends, the context menu not suppressed, a Ctrl press not ignored, no chord on left plus right, a missing hit test read as cell 0, the old cell not redrawn without the ring, the ring not drawn) failed a test each time. No engine, protocol or server code changed, no ADR, no open decision settled, no new dependency, no new canonical name (`InputController` was in the table; `InputControllerOptions` is not canonical). `ARCHITECTURE.md` gains "Input controller", `DECISIONS.md` the settled note and a section for the tasks that follow, `DEVELOPMENT_GUIDE.md` the input tests, `README.md` the controls, and `docs/milestones/M3-local-solo-client.md` the `setCursor` member. Not checked by the author: the ring and the controls in a real browser (the board is not on a screen until M3-T05), `pnpm test:browser`, and CI on GitHub.
- **M3-T03** Canvas board renderer. `apps/web/src/render/` gets `BoardRenderer` (`mount`, `render`, `hitTest`, `resize`, `unmount`, exactly as the task fixes it), `CanvasBoardRenderer`, and `BoardCanvas`, a React component that takes a `view` (never a session) and owns the renderer's lifetime. The renderer works in whole device pixels (`boardLayout.ts`: cells of 16 to 40 CSS pixels that fill the width of the canvas's parent, a one-pixel gap, and a horizontal scroll when the width is too small for the minimum), so the board is crisp at any pixel ratio. It keeps one visual code per cell (`cellVisuals.ts`: hidden, flag, revealed 0 to 8, mine, wrong flag) and redraws only the cells whose code changed since the last view; a view that shows the same as the last one draws nothing. After a loss a closed mine shows as a mine, a flag on a mine stays a flag and a flag on a safe cell is a flag with a cross; after a win the remaining mines show as flags; a view without `exposedMines` is drawn as it is, so the same code serves a race, where the server withholds them (D-14). Flag, mine and wrong flag differ by shape, not only by color. Colors and font come from the `--ms-*` tokens (`boardTheme.ts`), read again on every `resize()`. `hitTest(clientX, clientY)` converts by the size the canvas has on screen, so zoom and transforms work, and returns `null` in a gap, outside the board, for a non-finite value, and before the first view; a click between two cells never opens a neighbor. `BoardCanvas` calls `resize()` when its container is resized, the window is resized, the pixel ratio changes, the system switches between light and dark, or `data-theme` changes, hands the renderer to `onRenderer` (for the input controller of M3-T04), and shows a message instead of a canvas when the browser gives no 2D context. 127 new tests (913 in all): 39 layout (including a per-pixel check that `cellAt` agrees with `cellRect` on seven boards at four pixel ratios), 9 visuals, 3 theme, 55 renderer, 15 component, 6 on the contrast of the glyph colors in every theme. jsdom has no canvas, so the renderer is tested against a recording fake of the 2D context (`apps/web/test/fakeCanvas.ts`); no `node-canvas` and no new dependency. A hand mutation check (redraw every cell each time, `hitTest` scaled by `devicePixelRatio` only, a click in a gap goes to the neighbor, theme not read again, wrong flag drawn as a flag, no window resize listener) failed a test each time. The documented budget for a full redraw of an expert board (30x16) is at most 8 canvas calls per cell and 50 ms with the fake context, and 25 calls for a one-cell change; measured at the time of writing: 4.2 calls per cell and about 1.6 ms. No engine, protocol or server code changed, no ADR, no open decision settled, no new dependency; `BoardRenderer` and `CanvasBoardRenderer` were already canonical names, `BoardCanvas` and the helpers (`BoardLayout`, `BoardTheme`, `computeLayout`, `cellRect`, `cellAt`, `computeVisuals`, `VISUAL`, `readBoardTheme`) are not and are not public API. `ARCHITECTURE.md` gains "Rendering", `DECISIONS.md` a note for the tasks that follow, `DEVELOPMENT_GUIDE.md` the renderer tests, and `README.md` its status line. Not checked by the author: the board in a real browser (the manual check on an expert board is the developer's), CI on GitHub, `pnpm test:browser`. The look of the glyphs was checked once on PNGs rasterized from the real renderer with a scratch `@napi-rs/canvas` outside the repository.

- **M2-T05** Results and scoring. `Game.result()` returns `undefined` until the game is won or lost, then one frozen `GameResult { outcome: 'won' | 'lost'; timeMs; safeCellsRevealed; totalSafeCells; effectiveCommands; threeBV; threeBVPerSecond }`, the same object on every call. `timeMs` is the `t` of the finishing command (0 for a game that the opening cleared at creation); `safeCellsRevealed` is the revealed count, including the safe neighbors a losing chord opened and the opening; `effectiveCommands` is the length of the command log (flags included); `threeBV` is the board's Bechtel's Board Benchmark Value (one click per opening plus one per numbered cell that touches no zero), computed with an explicit stack; `threeBVPerSecond` is `threeBV * 1000 / timeMs`, a single division, and 0 when `timeMs` is 0. `replay(log).result()` equals the live result, also through JSON. `GameResult` is the only new public name (the surface is 30 names; `api-surface.txt` gains `result()` and `GameResult`, and the `GameStatus` line is printed in another union order, which is the same type); `computeThreeBV` and `buildGameResult` are internal and on the not-public list. - **M2-T04** `ReplayLog` and `replay`. `ReplayLog` is `{ version: 1; config; seed; commands }`. `validateReplayLog(log)` throws `InvalidReplayError` at the first problem, in a fixed order: `version`, `config` (the `InvalidBoardConfigError` is kept as `cause`), `seed` (uint32), `commands` (an array of at most 100,000 entries, counted before any entry is read), then each command's `type`, `index` (inside this log's board) and `t` (non-negative safe integer, not lower than the one before; equal is fine). `replay(log, generator?)` validates, builds the game with `createGame` and applies every command; it throws `InvalidReplayError` (reason starts `commands[i]`) for a command the game does not accept, because a log holds only accepted commands, and reports a config with no room for a safe opening as `InvalidReplayError` with the generator's error as `cause`. An empty log replays to `'ready'`, or to `'won'` on a board that the opening already clears. New class `InvalidReplayError` (`reason` starting with where the problem is, standard `cause`); the task text names it and the canonical table lacked it, so it is added to the `engine` row. The public surface is 29 names (`ReplayLog`, `replay`, `validateReplayLog`, `InvalidReplayError` added; `api-surface.txt` shows exactly those four); `MAX_REPLAY_COMMANDS` stays internal and is on the not-public list. New `replay.test.ts` (95 tests, including three fast-check properties: round trip of random and guided games over 1,000 cases, the same through JSON, and a repeated accepted reveal rejected at its position), 6 tests in `errors.test.ts`, 2 consumer tests in `public-api.test.ts`; the suite goes from 473 to 576 tests and `replay.ts` has 100% statement and line coverage. A 16-mutant check of `replay.ts` is caught in full. `ARCHITECTURE.md` gains "Replay and validation" with the versioning rule; `DECISIONS.md` gains a note for the ADRs that follow. No ADR, no open decision settled, no new dependency.

- **M2-T01** In-engine PRNG. `createPrng(seed)` returns a `Prng` (`nextUint32`, `nextInt(maxExclusive)`) built on sfc32 with its state expanded by a 32-bit SplitMix and a 12-output warm-up, using only 32-bit integer arithmetic. `nextInt` is unbiased (rejection sampling).
