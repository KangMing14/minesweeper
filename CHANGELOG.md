# Changelog

All notable changes to this project are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Entries are drafted from the conventional commits at task close-out and then curated by hand; each names its task ID. Versions start at `v0.<n>.0` for pre-launch releases and `v1.0.0` at public launch (see [DEVELOPMENT_GUIDE.md](DEVELOPMENT_GUIDE.md), "Tags and releases").

## [Unreleased]

### Added
- **M2-T04** `ReplayLog` and `replay`. `ReplayLog` is `{ version: 1; config; seed; commands }`. `validateReplayLog(log)` throws `InvalidReplayError` at the first problem, in a fixed order: `version`, `config` (the `InvalidBoardConfigError` is kept as `cause`), `seed` (uint32), `commands` (an array of at most 100,000 entries, counted before any entry is read), then each command's `type`, `index` (inside this log's board) and `t` (non-negative safe integer, not lower than the one before; equal is fine). `replay(log, generator?)` validates, builds the game with `createGame` and applies every command; it throws `InvalidReplayError` (reason starts `commands[i]`) for a command the game does not accept, because a log holds only accepted commands, and reports a config with no room for a safe opening as `InvalidReplayError` with the generator's error as `cause`. An empty log replays to `'ready'`, or to `'won'` on a board that the opening already clears. New class `InvalidReplayError` (`reason` starting with where the problem is, standard `cause`); the task text names it and the canonical table lacked it, so it is added to the `engine` row. The public surface is 29 names (`ReplayLog`, `replay`, `validateReplayLog`, `InvalidReplayError` added; `api-surface.txt` shows exactly those four); `MAX_REPLAY_COMMANDS` stays internal and is on the not-public list. New `replay.test.ts` (95 tests, including three fast-check properties: round trip of random and guided games over 1,000 cases, the same through JSON, and a repeated accepted reveal rejected at its position), 6 tests in `errors.test.ts`, 2 consumer tests in `public-api.test.ts`; the suite goes from 473 to 576 tests and `replay.ts` has 100% statement and line coverage. A 16-mutant check of `replay.ts` is caught in full. `ARCHITECTURE.md` gains "Replay and validation" with the versioning rule; `DECISIONS.md` gains a note for the ADRs that follow. No ADR, no open decision settled, no new dependency.
- **M2-T03** `createGame` and the command log. `createGame(config, seed, generator?)` builds the board with the generator (default `SeededBoardGenerator`) and returns a game with its safe opening already revealed at `t = 0`; the opening is not a command, is not logged and announces no event. The `Game` constructor gains an optional `opening` (`new Game(board)` is unchanged). The status stays `'ready'` until the first accepted command; if the opening already clears the board the game is `'won'` at creation (decided 2026-11-19, option A1; recorded in `ARCHITECTURE.md` and noted in `DECISIONS.md`). `Game.log()` returns the accepted commands as a new frozen list of frozen copies (`type`, `index`, `t`); invalid commands, no-ops, commands after the end and commands with a bad `t` are not logged, and a command is logged before its events are delivered. `Game.apply` now rejects (returns `[]`) a command whose `t` is not a non-negative safe integer or is lower than the last accepted command's `t` (Review Focus #2); the index is still checked first and still throws. The public surface is 25 names (`createGame` added; `api-surface.txt` updated for it, `log()` and the constructor). `game.property.test.ts` now generates non-decreasing `t`; its assertions are unchanged. New `create-game.test.ts` (22 tests) and `game.log.test.ts` (29 tests, with a 1,000-case property), one consumer test in `public-api.test.ts`; the suite goes from 420 to 473 tests, and `game.ts` and `create-game.ts` have 100% coverage. `ARCHITECTURE.md` gains "Game creation and the command log"; `DECISIONS.md` gains a note for the ADRs that follow. No ADR, no open decision settled, no new dependency.
- **M2-T02** Seeded board generator and safe opening. `SeededBoardGenerator.generate(config, seed)` returns a frozen `GeneratedBoard { board, opening }`: the opening cell and its neighbors hold no mine, so it shows 0 and cascades, and the mines are placed by a partial Fisher-Yates shuffle over the other cells using the in-engine `Prng`. `SafeOpeningPolicy.select(config, prng)` picks the center with one draw; the generator takes an optional policy. A config whose mines fit around no opening zone (for example 78 mines on 9x9) throws `InvalidBoardConfigError` (reason starts `mineCount`), for every seed; 1xN, 2x2 and 1x1 boards are valid or rejected clearly (Review Focus #4). Four public names are added (24 in all; `api-surface.txt` updated); `openingZone` is internal. New `fixtures/boards.json` (22 golden boards: opening and SHA-256 of the mine list, produced by a plain reference implementation of the contract rather than by the generator, which agrees with it), `opening.test.ts`, `generator.test.ts` (including a plain reference implementation and a distribution check) and `generator.golden.test.ts` (with a test-only SHA-256, no `node:crypto`). The suite goes from 320 to 420 tests; `opening.ts` and `generator.ts` have 100% coverage. `ARCHITECTURE.md` gains "Board generation"; `DECISIONS.md` gains a generator-stability note. No ADR, no new dependency, no open decision settled.
- **M2-T01** In-engine PRNG. `createPrng(seed)` returns a `Prng` (`nextUint32`, `nextInt(maxExclusive)`) built on sfc32 with its state expanded by a 32-bit SplitMix and a 12-output warm-up, using only 32-bit integer arithmetic. `nextInt` is unbiased (rejection sampling). A seed must be an integer from 0 to 4294967295 and `maxExclusive` an integer from 1 to 4294967296, else `RangeError`; a rejected argument does not move the generator. Both names are public (the surface goes from 18 to 20 names; `api-surface.txt` updated). New `packages/engine/fixtures/prng-vectors.json` (golden vectors from a third-party sfc32 and the published splitmix32, not from engine code) and `prng.test.ts` (66 tests, including a BigInt differential check); one consumer test in `public-api.test.ts`. The suite goes from 253 to 320 tests. `tsconfig.test.json` of `engine` gains `resolveJsonModule` so tests can import the fixture. `ARCHITECTURE.md` gains "Seeded randomness"; `DEVELOPMENT_GUIDE.md` ("Where tests live") records the `fixtures/` convention. The sequence for a seed is now a stable contract (ADR-002). No new dependency, no ADR.

A guard on a fixed-seed sample of 1,000 games needs at least 300 effective chords, 50 losing chords and 3 chords that win the game (the blind generator of `game.property.test.ts` gave 3 effective chords in 1,034 tries; the guided one gives about 650); a differential test compares `Game` with a recursive reference written from ADR-009 after every command; one more property says a chord whose flags sit exactly on the real mines never loses. - **M1-T06** Win, loss and the end of a game in `Game.apply`. The game is won when every safe cell is revealed, by a `reveal`, a cascade or a `chord` (so the M1-T05 follow-up, a chord that opens the last safe cell, now wins): the command's events are `cellsRevealed` then one `gameWon { t }`, and the status becomes `'won'`. Flags play no part. Win and loss are final: every later command of any type returns `[]`, delivers nothing and leaves the view identical, and only an index outside the board still throws `RangeError`. A won game exposes its mines like a lost one (`exposedMines`; the D-14 filter for races stays with the server, M5-T05). `Game` keeps a running revealed count and settles `reveal` and `chord` in one internal step, so every event of a command reaches every subscriber. New tests: `lifecycle.test.ts` and `game.property.test.ts`, with `fast-check` 4.10.2 (new exact devDependency, 1,000 cases per property). Three existing tests changed because a cascade or chord that opens every safe cell now also wins (`game.test.ts`). 40 tests added (202 to 242), 100% coverage kept. `ARCHITECTURE.md` gains a "Win, loss and the end of a game" section; `DECISIONS.md` gains the `fast-check` pin and verification notes. No ADR, no open decision settled, no new canonical name or export.
- **M1-T05** Flags and chording in `Game.apply`, and ADR-009. `flag` toggles a hidden cell to flagged and back (`flagToggled`), does nothing on a revealed cell, and moves a `'ready'` game to `'playing'`. `chord` on a revealed number whose flagged neighbors equal its value opens every other hidden neighbor through the reveal path as one `cellsRevealed` (each cell once); flags are only counted, so a wrong flag can lose: the safe neighbors open first, then one `gameLost` names the lowest-index mine. A chord on a hidden or flagged cell, a zero, with too few or too many flags, or with nothing left to open returns `[]`. Every event of a command reaches every subscriber even if one throws; the first error is rethrown. New internal `chordCells` and `ChordResult` (not exported); no new public name. D-04 is settled by `docs/adr/ADR-009-cell-rules.md`. `ARCHITECTURE.md` gains a "Flags and chording" section. The two `TODO(M1-T05)` placeholders are gone. 42 tests added (160 to 202).
- **M1-T04** `Game.apply` and the reveal rules. New `Command` type (`{ type: 'reveal' | 'flag' | 'chord'; index; t }`, the canonical shape). `reveal` opens a hidden safe cell and, for a 0, spreads over its neighbors with an iterative flood fill (explicit stack, no recursion): one `cellsRevealed` event per command, cells listed clicked-first then in a fixed discovery order. `reveal` on a mine loses the game with one `gameLost`; the mine cell stays hidden and shows only through `exposedMines`. A reveal on a revealed or flagged cell, and any command after a loss, returns `[]` and changes nothing; an index outside the board throws `RangeError` for every command type. `flag` and `chord` are accepted and ignored until M1-T05; winning is detected from M1-T06. Tests: the 480-cell expert board and the 100x100 board (which a recursive fill fails) cascade in one command. `ARCHITECTURE.md` gains a "Reveal and flood fill" section. No ADR, no open decision settled, no new canonical name.
- **M1-T03** `Game`, its view and its events. `new Game(board)` starts `'ready'` with every cell hidden; `view()` returns a fresh, deeply frozen `GameView` (`CellView` per cell, `revealedCount`, `flagCount`, `minesRemaining`, and `exposedMines` only when the game is won or lost); `subscribe(listener)` returns an unsubscribe function. `GameEvent` is a union of `CellsRevealed`, `FlagToggled`, `GameWon` and `GameLost`, discriminated by a camel-case `type` (the docs did not fix the strings). Hidden cells carry no mine information, shown by tests that give two different layouts the same serialized view. `ARCHITECTURE.md` gains a "Game state, views and events" section, including the D-14 note for the server. No new public name beyond the canonical ones; `apply` arrives in M1-T04.
- **M1-T02** `Board`: an immutable mine layout with `isMine`, cached and frozen `neighbors` (ascending order, no allocation after the first call), `adjacentMines`, `indexOf`, `coordsOf` and `readonly config`. The constructor validates the config, collapses repeated mines, and rejects out-of-range mines (`RangeError`) and a distinct-mine count that differs from `mineCount` (`InvalidBoardConfigError`, reason starts with `mineCount`). `ARCHITECTURE.md` gains a "Board and neighbor math" section. No new error class, no new canonical name besides `Board`.
